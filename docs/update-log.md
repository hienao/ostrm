# 更新历史

本文档记录了 OpenList to Stream 的所有版本更新内容，帮助用户了解新功能、改进和修复的问题。

## 当前版本

### v2.6.0 (2026-08-02)

#### ✨ 新功能
- 🔔 **Apprise 任务通知**：普通 STRM 任务和手动刮削到达终态后，可按成功、部分完成或失败发送通知，并由 Apprise 路由到一个或多个下游渠道
- 📋 **分类异常明细**：通知按结构异常跳过、刮削未识别、目录重命名失败、文件重命名失败、文件处理失败和媒体库刷新失败分组展示路径与原因
- 🔄 **Emby / Jellyfin 媒体库刷新**：系统设置可管理多个媒体服务器，任务完成后可选择刷新全部媒体库或按媒体库 ID 精确刷新指定媒体库
- ✏️ **普通任务自动重命名**：任务可选择在生成 STRM 前，根据 TMDB 结果重命名 OpenList 中的媒体目录和文件；该选项默认关闭

#### ⚡ 功能与体验优化
- 🎯 **精确刷新保护**：刷新指定媒体库前重新校验媒体库 ID，不按名称猜测目标，媒体库失效时也不会回退为全部刷新
- 💤 **增量刷新抑制**：增量任务没有视频变更、失效 STRM 清理或媒体重命名时，不向媒体服务器提交无效刷新请求
- 📍 **完整路径控制**：通知可选择显示完整源路径，关闭后仅保留末级目录或文件名；每类异常明细可限制为 1–20 条
- 🧭 **结构异常通知**：主动跳过的结构异常视频会显示完整路径和校验原因，但不会单独把成功任务标记为部分完成
- 🪟 **弹窗滚动优化**：任务及 OpenList 配置弹窗限制在当前视口内，标题与底部操作按钮固定，中间表单区域独立滚动
- 💬 **社区入口**：Web 页脚和 README 增加 Telegram 群组 `@ostrm6` 入口
- 📚 **使用文档**：新增 Emby/Jellyfin 媒体库刷新和 Apprise 任务通知指南，并补充任务自动重命名、失效媒体库处理与排错说明

#### 🛡️ 稳定性优化
- 🔒 **媒体服务器配置保护**：停用的服务器不能继续用于任务刷新；仍被任务引用的服务器配置禁止删除
- 🧯 **刷新失败隔离**：媒体库刷新失败不会回滚已经生成的 STRM，任务通知会标记为部分完成并展示具体原因
- 🔁 **通知失败隔离**：Apprise 通知使用独立线程发送，失败会重试一次，最终失败只记录日志，不改变任务或手动刮削结果
- 🧩 **服务启动修复**：修复媒体服务器 API 服务的依赖注入构造方式，避免容器启动时出现 Bean 创建失败

#### ⚠️ 兼容性说明
- 数据库迁移会自动新增普通任务自动重命名开关、媒体服务器配置表和任务刷新字段，无需手工修改数据库
- 已有任务的自动重命名默认关闭、媒体库刷新默认关闭，升级后保持原有执行行为
- Apprise 通知默认关闭；启用前需要部署 Apprise API，并在系统设置中填写服务地址、Config ID 和通知标签
- 精确刷新依赖 Emby/Jellyfin 返回的媒体库 ID 和目录路径；升级后请先在系统设置中测试连接，再为任务选择目标媒体库

详细配置请参阅 [Emby / Jellyfin 媒体库刷新](./media-server-refresh.md) 和 [Apprise 任务通知](./notifications.md)。

### v2.5.0 (2026-08-01)

#### ✨ 新功能
- 🎬 **任务媒体库类型**: OpenList 任务可指定自动识别、电影、电视剧或动画，并按类型使用对应的目录结构和媒体解析规则
- 🌳 **目录结构检查与过滤**: 支持按需检查任务根目录及第一层媒体目录，以文件树展示异常；任务可选择跳过结构不符合要求的视频
- 🧹 **手动刮削**: 支持目录树选择、AI/TMDB 预览、标题与年份修正、TMDB ID 直查，以及 NFO、海报和背景图写回 OpenList
- ✏️ **安全重命名**: 电影目录和文件可包含 TMDB ID；电视剧支持根目录、季目录和媒体文件分阶段重命名，季目录可从复合名称中识别明确季标记
- ⏳ **异步刮削作业**: 手动刮削立即返回作业 ID，前端展示阶段进度；失败后可从重命名、下载或上传检查点继续
- 🚦 **OpenList 双层限流**: 每个 OpenList 配置可同时限制文件 API 的 QPS 与 QPM

#### ⚡ 性能与体验优化
- 🗂️ **目录索引复用**: STRM 生成、字幕复制、刮削和清理共享单次任务目录快照，减少重复 OpenList API 调用
- 📋 **增量任务清单**: 未变化媒体跳过重复生成和刮削，降低大媒体库任务耗时
- 🌊 **流式文件传输**: 图片、NFO 和字幕改为流式下载，降低峰值内存占用
- 🔄 **按需加载**: 手动刮削和目录检查首次只读取必要层级，展开或检查时再读取子目录
- 📜 **日志页面优化**: 支持增量刷新、暂停加载与跟随、精确筛选、单条复制和安全清空；清空后无需重启容器

#### 🛡️ 稳定性优化
- 🧱 **AI 结构化输出**: 使用内置 System Prompt、JSON Schema 和响应语义校验，异常响应重试后安全回退本地解析
- 🔒 **任务互斥与幂等恢复**: 手动刮削未完成时禁止重复刮削或再次改名，重试会识别已经完成的操作
- 🔗 **特殊路径兼容**: 修复中文、空格、花括号及签名参数导致 OpenList 下载 URL 非法的问题
- 🎯 **季目录安全识别**: 支持 `第4季`、`Season 4`、`S04`、中文数字和特别篇；不同季号并存时拒绝自动改名，避免误判普通名称

#### ⚠️ 兼容性说明
- 数据库迁移会自动新增媒体库类型、QPS 限制、手动刮削作业及结构过滤字段，无需手工修改数据库
- 已有任务默认使用“自动识别”，结构过滤默认关闭，升级后保持原有生成行为
- AI 自定义提示词已取消，升级后统一使用服务端预置规则

### beta-v2.5.12 (2026-08-01)

#### 🛠️ 功能优化

- 🔒 **校验逻辑隔离**: 包含匹配只用于手动刮削的季目录重命名，不改变目录结构检查使用的严格季目录规则

### beta-v2.5.7 (2026-07-31)

#### ⚡ 性能优化
- 🗂️ **任务目录索引复用**: 单次任务只构建一次 OpenList 目录快照，STRM 生成、字幕复制、刮削和清理共享索引，减少重复目录 API 调用
- 🔁 **文件级任务去重**: 同一媒体文件在同批任务中只处理一次，并统一清理过期快照，降低重复生成与内存占用
- 🎬 **刮削会话缓存**: 同一媒体在任务内复用 TMDB 匹配、详情、季信息和现有 NFO 结果，优先利用已有元数据
- 🌊 **流式文件传输**: 图片、NFO 和字幕下载改为流式处理，避免大文件完整载入内存
- 📋 **增量任务清单**: 保存已生成文件的远端特征，未变化媒体跳过重复生成和刮削，任务完成后自动更新清单
- 🚀 **并发目录发现**: 在 OpenList QPS/QPM 限流保护下并发读取独立子目录，提高大媒体库遍历效率
- 🔎 **手动预览短缓存**: 短时间内重复预览复用识别结果，减少重复 AI、TMDB 和目录查询
- ⚙️ **系统配置快照缓存**: 配置读取使用不可变内存快照，并在配置修改后立即失效，减少高频磁盘解析和对象复制

#### 🛠️ 功能优化
- 🔄 **目录检查强制刷新**: 每次进入目录结构检查或检查子目录时主动刷新 OpenList，避免展示过期目录内容
- 🧹 **任务结束资源回收**: 无论任务成功或失败都会清理目录索引和刮削会话，控制长期运行时的内存占用

## 升级指南

### 从旧版本升级

#### 1. 备份数据
升级前务必备份重要数据：
```bash
# 备份配置和数据库
tar -czf backup-$(date +%Y%m%d).tar.gz ./data/

# 备份 STRM 文件
tar -czf strm-backup-$(date +%Y%m%d).tar.gz ./strm/
```

#### 2. 停止应用
```bash
# Docker Compose 部署
docker-compose down

# Docker 直接部署
docker stop openlist-strm
```

#### 3. 拉取新版本
```bash
# 拉取最新镜像
docker pull hienao6/openlist-strm:latest

# 或指定版本
docker pull hienao6/openlist-strm:v1.1.1
```

#### 4. 重新启动
```bash
# Docker Compose 部署
docker-compose up -d

# Docker 直接部署
docker run -d \
  --name openlist-strm \
  -p 3111:80 \
  -v ./data/config:/maindata/config \
  -v ./data/db:/maindata/db \
  -v ./logs:/maindata/log \
  -v ./strm:/app/backend/strm \
  --restart always \
  hienao6/openlist-strm:latest
```

#### 5. 验证升级
1. 访问应用确认正常运行
2. 检查任务配置是否完整
3. 测试一个任务执行
4. 查看日志确认无错误

### 配置迁移
某些版本升级可能需要配置迁移：

#### v1.2.0 重大升级迁移指南

⚠️ **重要提示**: v1.2.0 是重大架构更新，**不支持直接升级**，需要手动迁移数据。

**迁移步骤**:

1. **停止旧版本容器**
```bash
docker-compose down
```

2. **备份现有数据**
```bash
# 创建备份目录
mkdir -p ./backup/v1-backup

# 备份数据库文件
cp -r ./data/config/db ./backup/v1-backup/

# 备份配置文件
cp -r ./data/config/*.json ./backup/v1-backup/

# 备份日志文件
cp -r ./data/log ./backup/v1-backup/

# 备份STRM文件
cp -r ./strm ./backup/v1-backup/
```

3. **清理旧容器和镜像**
```bash
docker-compose down --rmi all --volumes --remove-orphans
```

4. **创建新的目录结构**
```bash
# 创建标准化的数据目录
mkdir -p ./data/config ./data/db ./logs ./strm
```

5. **迁移数据到新结构**
```bash
# 迁移数据库文件 (从 /app/data/config/db 到 /maindata/db)
cp ./backup/v1-backup/db/* ./data/db/

# 迁移配置文件 (从 /app/data/config 到 /maindata/config)
cp ./backup/v1-backup/*.json ./data/config/

# 迁移日志文件 (从 /app/data/log 到 /maindata/log)
cp ./backup/v1-backup/log/* ./logs/

# STRM文件路径不变
# ./strm → /app/backend/strm (保持一致)
```

6. **更新环境配置**
```bash
# 复制新的环境配置模板
cp .env.docker.example .env

# 根据需要编辑配置
# 默认配置已经适配新的目录结构
```

7. **启动新版本**
```bash
# 使用新的镜像名称构建并启动
docker-compose build
docker-compose up -d
```

8. **验证迁移**
- 访问 `http://localhost:3111` 确认应用正常
- 检查任务配置是否完整迁移
- 测试一个任务执行
- 查看日志确认无错误

**主要变更**:
- ✅ 镜像名: `hienao6/openlist-strm:latest`
- ✅ 数据库路径: `/maindata/db` (之前: `/app/data/config/db`)
- ✅ 配置路径: `/maindata/config` (之前: `/app/data/config`)
- ✅ 日志路径: `/maindata/log` (之前: `/app/data/log`)
- ✅ STRM路径: `/app/backend/strm` (保持不变)

**迁移注意事项**:
- 🔄 **手动迁移**: 必须手动复制数据文件
- 📁 **路径变更**: 容器内路径结构完全重新设计
- 🔧 **配置更新**: 使用新的环境变量配置方式
- ✅ **数据兼容**: 数据库格式和配置文件格式保持兼容

#### v1.0.x → v1.1.x
